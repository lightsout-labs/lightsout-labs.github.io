summary: "代码和测试都是 Agent 写的，PR 自动合并。我们的看法：写代码的人不再重要，规格和验证才重要。"
---

我们的电子表格应用 Gridworks 已经上线了。它的仓库里有 58 个合并过的 PR，没有一个是人看过的。代码和测试都是 Agent 写的，PR 也是它开的，CI 一通过就自动合并，合并完自动部署。

那一周我们做的事很少：回答 Agent 整理需求时提的问题，在需求和设计两道关上输入 approve，后来又批准了 5 次需求变更，用过应用之后提了 5 个 issue。代码一次都没打开过。

![Gridworks 已合并的 58 个 PR](public/figures/gridworks-merged-pulls.png)

我们的看法很直接：只要需求写清楚，验证的办法也写下来，Agent 就能在没人看着的情况下把软件做出来。人写不写代码已经不重要了，重要的是规格说明，以及约束 Agent 产出的那些检查。

先说做出来的是什么。Gridworks 是浏览器里的电子表格，能打开和保存真正的 .xlsx 文件，能排序、筛选、冻结窗格、做条件格式和数据验证、打印，断网也能用。第一次提交在 11 月 13 日晚上，最后一个 PR 在 11 月 20 日下午合并，不到七天。产品代码 25,651 行，实现了 184 个 Excel 函数，单元测试 470 多个，端到端测试 130 多个，在三个浏览器里各跑一遍。读写 .xlsx 的代码也是 Agent 自己写的：它测出 ExcelJS 载入 11 MB 文件要 4.5 秒，达不到需求，就记下一条架构决策，换成自己的实现。

我们这一周的日常很单调：在终端里输入 /nightshift:build，Agent 找到第一个没做完的切片，拉分支，写测试，写代码，跑检查，交给评审，开 PR，等 CI 通过后合并，然后停下。我们输入 /clear 清空上下文，再输入一次 /nightshift:build。大部分时间我们在做别的事，回来打开线上的 Gridworks 试一试新功能。

做的过程中需求改了 5 次，比如加上 Excel 的 Point 模式，把启动时的整屏列表换成对话框。每一次都是先改需求文档，等我们批准，再插入新的切片照常开发。

没人读代码，不等于没人管质量。读代码这件事被拆成了五样东西，都写在仓库里，每个 PR 都会执行。

需求是 Agent 唯一的依据，设计、验收标准、测试都从它来。每个切片先写测试，确认测试因为功能不存在而失败，再写代码，规则不允许为了通过检查削弱测试。做完的切片交给另一个只读的评审 Agent，它看不到写代码时的对话。40 个切片里有 21 个被它挡下过，比如它发现单元格链接会存下并打开 javascript: 开头的地址。硬规则放在模型之外运行的 hook 里：Agent 改不了批准状态，提交不了 main，检查不过就结束不了切片。最后是 CI 和三道关，检查全过才自动合并，人只在批准需求、批准设计、验收交付三处做决定。

![nightshift 的五个阶段和三道关](public/figures/stages-and-gates.zh.png)

再说一个缺陷是怎么修好的。11 月 18 日，我们输入 =DATE(2026,11,18)，单元格显示的是 46344，这是 Excel 内部存这一天用的序列号。我们提了 issue #40，里面只写了每个公式应该显示什么、现在显示什么。之后 Agent 把它变成一个修复切片，先写测试，再改代码，评审，合并，issue 自动关闭，新版本上线。下午 5 点 23 分规划合并，5 点 40 分修复合并。

回头查原因：负责日期函数的切片，验收标准写着“使用 Excel 的序列号”，测试照着检查，全部通过。每一项检查都没错，错在验收标准没说用户看到的应该是日期。缺陷出在规格上，修也是修在规格上，整个过程没有人读代码。

同一份需求交给 Agent 做两遍，代码不会一样。我们的看法是：只要验证是完整的，每一份结果都满足需求，不同只落在需求没规定的地方。工程师的功夫要从写代码、读代码，挪到把需求写到可以检验、把检验写到可以自动执行上。回头看，这一周我们写下的东西全是规格：回答提问，批准需求和变更，提 issue。#40 的正文就是一张对照表，Agent 几乎原样把它变成了验收标准。写一个好 issue 和写一组好测试，用的是同一种功夫。

这次证明的东西也有边界：只有一个产品，用 TypeScript 写，做了不到七天，还没经历长期维护，第三道关还没过。日期缺陷说明验证这次并不完整，验证能多完整，取决于需求写得多清楚，这一步现在还靠人。

如果你不信，可以自己做一遍。Gridworks 批准过的需求文档就在仓库里，用 nightshift 或你自己的流程从头做一遍，再和我们的结果比一比。
